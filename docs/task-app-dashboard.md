# Задача: личный dashboard ученика (/dashboard)

Мокап: `docs/mockups/app-shell-dashboard-mockup.html`, экраны 1 (обычное
состояние), 2 (новичок, is_new_user) и 4 (мобильная раскладка). Каркас
app-области готов (task-app-shell + task-people-in-app-shell) — эта
задача наполняет заглушку AppDashboardPage.

## СТОП-проверка

1. Бэкенд поднят, `npm run gen:api` выполнен, schema.d.ts закоммичен
   и свежий.
2. Открой в schema.d.ts ответ `GET /api/dashboard/` и сверь с этой
   задачей. Если состав полей расходится с описанным ниже —
   ОСТАНОВИСЬ и сообщи, не додумывай.
3. Псевдоним `Dashboard` уже есть в types/api.ts — используй его.

## Контекст

`GET /api/dashboard/` — личный учебный дашборд (доступен любой сессии):
сводка прогресса, continue, recommended, recently, флаг `is_new_user`.
Данные грузятся ОДИН раз, без поллинга (правило проекта). Бэкенд не
меняется, миграций нет.

## Что сделать

### 1. Данные

- `api/dashboard.ts` — функция запроса (по образцу существующих
  api/-модулей, client.ts не трогать).
- Хук `useDashboard` — паттерн «номер попытки», как useMasterDashboard /
  useUsersList: loading / error / data + retry. Ошибка → состояние
  страницы с кнопкой Retry и текстом бэка (utils/apiError).
- Запрос уходит только в app-области (master сюда не попадает —
  AreaGate уже уводит его; отдельного гейта в странице не нужно,
  но убедись, что это так).

### 2. Страница AppDashboardPage (по мокапу)

Обычное состояние (is_new_user = false):

- Приветствие: «Good day, {имя}» + каптион «Your learning overview»
  (имя — из useAuth, как у master; ключи i18n).
- **Continue learning** — мятная hero-карточка (teal-50): превью-заглушка
  с play-иконкой, eyebrow, название урока, meta, прогресс-бар
  (трек полубелый, заливка accent) + процент, кнопка «Continue
  lesson →» (accent, radius-xs). Если continue в ответе пуст, а
  is_new_user = false — блок просто не показывается.
- **Сводка** — три stat-карточки: Overall completion (%), Lessons
  completed, In progress. Посмотри StatCard у master: если
  переиспользуется — переиспользуй, если завязан на master-специфику —
  сделай app-вариант и объясни в отчёте.
- **Recommended for you** — сетка карточек уроков (превью-градиент
  с play-иконкой, название, meta), ссылка «All lessons →» на
  APP_PATHS.lessons. Пустой список → секция скрыта.
- **Recently watched** — компактный список: мини-превью, название,
  статус точка + текст (переиспользуй StatusBadge; цвета статусов —
  токены --color-status-*). Пустой список → секция скрыта.

Состояние новичка (is_new_user = true):

- Вместо Continue, сводки и Recently — мятный empty-блок по экрану 2:
  play-иконка в круге, «Start your first lesson», подпись, кнопка
  «Browse lessons →» на APP_PATHS.lessons.
- Recommended показывается, если бэкенд его отдал.

Мобильная раскладка — экран 4: continue-карточка складывается в
столбик, сводка остаётся тремя маленькими карточками в ряд, сетка
Recommended в одну колонку. Mobile-first, брейкпоинт 600 (как в
области принято).

### 3. Ссылки на уроки — ВРЕМЕННОЕ решение

Страницы урока ещё нет (она в плане после каталога). Поэтому:

- кнопки «Continue lesson» и «Browse lessons» и карточки Recommended /
  строки Recently ведут на APP_PATHS.lessons (каталог-заглушку);
- у перехода оставь TODO-комментарий «→ страница урока, когда появится
  роут»; никаких роутов урока в этой задаче не заводить.

### 4. Возможные расхождения с мокапом

- В мокапе в meta урока показано имя категории. Если в ответе
  dashboard имени категории НЕТ (только id или ничего) — имя НЕ
  показывать и НЕ тянуть дерево категорий отдельным запросом ради
  подписи. Отметь отклонение в отчёте.
- Формат длительности/позиции — m:ss, конвертация из секунд как
  в таблице уроков master (представление, не бизнес-логика).

### 5. Компоненты и i18n

- Новые компоненты — в components/app/ (ContinueCard, RecommendedGrid,
  RecentList и т.п. — имена на твоё усмотрение, по одному CSS Module
  на компонент). Сначала поищи переиспользуемое в ui/ и master/.
- Все строки — ключи i18n (блок app.dashboard.*).

## Дизайн

- Только токены. Кнопки/чипы — radius-xs (рабочая область, пилюль нет).
- Карточки — radius-lg, shadow-card. Ширина по --layout-max-width.

## НЕ трогать

- Бэкенд, master-область, каркас app (шапка/табы/роуты) — кроме
  замены заглушки dashboard на страницу.
- Учебные эндпоинты кроме GET /api/dashboard/ не вызывать.

## Проверки

Только статические: npm run build, eslint. Приложение не запускать.

## Testing guide для Jenna

Подготовка: контента в БД нет — через master завести 1–2 категории и
3–4 урока (Vimeo ID для теста: 76979871), часть уроков сделать
видимыми роли welder или public.

1. Войти свежесозданным welder (первый вход пройден, уроки не
   смотрел) → /dashboard: приветствие + empty-блок «Start your first
   lesson» (+ Recommended, если бэкенд отдал). Нулевой сводки нет.
2. Кнопка «Browse lessons →» → каталог-заглушка /lessons.
3. (Когда появится плеер, прогресс создастся сам; пока можно создать
   прогресс через Swagger: POST /api/progress/ под сессией welder.)
   Обновить /dashboard → continue-карточка с прогресс-баром, сводка
   с цифрами, Recently со статусами.
4. Сузить окно <600px → карточка continue в столбик, сводка в ряд,
   Recommended в одну колонку, табы на месте.
5. Выключить бэкенд (docker compose stop backend) → на /dashboard
   состояние ошибки с Retry; включить бэкенд, Retry → данные
   загрузились.
6. Войти как keimo → на /dashboard не попасть (redirect в master,
   как раньше), запрос дашборда из master-области не уходит
   (вкладка Network).
