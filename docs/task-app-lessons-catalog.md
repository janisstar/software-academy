# Задача: страница каталога уроков /lessons (interface-область app)

Наполнение страницы Lessons по утверждённому мокапу
`docs/mockups/app-lessons-catalog-mockup.html` (3 экрана: Mobile / Desktop /
Empty state). Каркас app-области (AppLayout, табы/шапка, роут /lessons)
уже существует — эта задача заполняет страницу, каркас НЕ трогает.

## СТОП-проверка (перед началом)

`src/api/schema.d.ts` свежий и закоммичен; `listLessons` и `useLessons`
уже в репо (прошлая задача). Если чего-то нет — ОСТАНОВИСЬ и сообщи.

## Образец — таблица уроков Content (ВАЖНО)

Раскладка уроков по группам уже решена в master-таблице уроков
(`/content/lessons`): порядок групп = ОБХОД ДЕРЕВА категорий (верхний
уровень → его подкатегории), уроки раскладываются по `category_id`,
внутри группы — порядок с бэка. Использовать ТОТ ЖЕ подход. Если логика
обхода там завёрнута в переиспользуемую функцию — переиспользовать;
если она вросла в компонент таблицы — вынести в общий util и подключить
в обоих местах (это не «удаление кода», а вынос, разрешён).

## Данные

- `useLessons()` — уроки со статусом (LessonWithStatus).
- `useCategoriesTree()` — дерево категорий (уже отфильтровано бэком
  по роли): имена групп, порядок, фильтр.
- НИКАКОЙ счётной логики на фронте: только раскладка двух серверных
  порядков (см. образец).

## Что рисуем (по мокапу)

### Группы
- Группа = категория из обхода дерева. Подкатегория — своя группа
  с капсовым надзаголовком родителя (eyebrow) над названием.
- Группы, в которых нет ни одного урока, НЕ рисуются.
- Счётчиков у категорий НЕТ (решение Jenna).
- Уроки, чей category_id не найден в дереве, не теряются молча —
  группа "Other" в конце (поведение как «Unknown category» в
  master-таблице, но ярлык учебный, без слова unknown).

### Карточка урока (components/app/)
- Вся карточка кликабельна → роут страницы урока
  (`/lessons/:lessonId` — сама страница урока будет следующей задачей;
  сейчас достаточно роута-заглушки, если его ещё нет, ИЛИ Link на
  будущий путь из constants/routes.ts).
- Содержимое: title; description одной строкой с многоточием;
  duration в формате m:ss с иконкой часов (утилиту форматирования
  переиспользовать из master-таблицы, если она там есть; иначе —
  общий util); статус.
- **Статус = точка + текст** (язык проекта): not started — серая
  точка + серый текст; in progress — бирюзовая + бирюзовый medium;
  completed — зелёная (--color-status-completed) + зелёный medium.
  Проверь, можно ли расширить существующий StatusBadge вариантами
  урока; если его варианты жёстко про пользователей (active/pending/
  locked) — новый маленький компонент LessonStatus в components/app,
  StatusBadge не ломать.
- **Полоска прогресса**: 3px по нижнему краю карточки, ширина =
  watch_percent, ТОЛЬКО у status === "in_progress". У остальных
  статусов полоски нет вообще (не пустая — отсутствует).
- Радиусы: карточка --radius-lg; никаких пилюль (app-область).

### Фильтр
- Селект категорий над списком (radius-sm, стрелка как у Select).
- Клиентский, как в master-таблице: выбор родителя показывает ТОЛЬКО
  его собственные уроки (подкатегории не включаются) — поведение
  каталога и master-таблицы должно совпадать.
- Формат опций — как в master-таблице уроков (дерево:
  «Родитель / Подкатегория»).
- "All categories" — по умолчанию.

### Раскладка
- Mobile-first: карточки одной колонкой; десктоп (≥900px) — сетка
  в 2 колонки, max-width --layout-max-width.
- Заголовок страницы: h1 "Lessons" + caption "Short guides for your
  daily tasks" (в i18n-ключи).

### Состояния
- Loading — как у соседних страниц-списков.
- Error — состояние страницы с текстом бэка (utils/apiError) + Retry.
- Empty (уроков нет вообще) — по экрану 3 мокапа: иконка в мятном
  круге, "No guides yet", подсказка спросить администратора компании.
- Отфильтровано в ноль (категория выбрана, уроков нет) — короткая
  строка "No guides in this category" + кнопка/ссылка сбросить фильтр
  (НЕ большой empty state — он про «вообще пусто»).

## i18n

Все строки — ключи в en.json (блок вида app.lessons.*). Хардкода нет.

## Границы (не трогать)

- AppLayout, навигация, роуты других страниц.
- Master-область целиком (кроме разрешённого выноса util обхода
  дерева, если он вросший, — с сохранением поведения master-таблицы).
- Бэкенд, schema.d.ts, useLessons/useCategoriesTree (использовать
  как есть; если чего-то не хватает — ОСТАНОВИСЬ и сообщи, не расширяй
  молча).

## Проверки (статические)

npm run build (tsc) и npm run lint — зелёные. Если выносился util
обхода дерева — build подтверждает, что master-таблица компилируется.

## Testing guide для Jenna

Подготовка: в БД нужен контент. Зайти как keimo (master) и создать
через Content: 2 верхние категории + 1 подкатегорию, 4–5 уроков
(Vimeo ID 76979871), часть public, часть — только роли welder,
один урок — роли inspector (welder его видеть не должен).

1. Войти как welder → /lessons: группы в порядке дерева, подкатегория
   с надзаголовком родителя, урок «для inspector» не виден, счётчиков
   нет.
2. Пустые для welder категории не отображаются.
3. Статусы: у нетронутых уроков «Not started» (серая точка).
4. Через Swagger POST /api/progress/ {lesson_id, watch_percent: 50} →
   обновить /lessons: «In progress», полоска ~половина ширины.
5. watch_percent: 95 → «Completed», полоски нет.
6. Фильтр: выбрать родителя с подкатегорией → видны только ЕГО уроки;
   выбрать категорию без уроков → «No guides in this category» +
   сброс фильтра работает.
7. Мобильный 375px: одна колонка, карточки удобны пальцу, табы снизу
   не перекрывают последнюю карточку.
8. Десктоп ≥900px: две колонки, шапка сверху, активен пункт Lessons.
9. Войти как admin → /lessons: виден ВЕСЬ каталог (privileged),
   страница та же.
10. Пользователь роли, у которой уроков нет вообще → большой empty
    state («No guides yet»).
