# Задача: аудит API для раздела Content (Categories + Lessons)

## Тип задачи

**ТОЛЬКО ЧТЕНИЕ И ОТЧЁТ. Никаких изменений кода, файлов, миграций.**
Это разведка перед проектированием master-интерфейса управления контентом.

## Контекст

Мы начинаем строить раздел Content для master: inline-дерево категорий,
таблица уроков, страница-форма урока с предпросмотром Vimeo, перестановка
порядка кнопками вверх/вниз. Прежде чем писать задачи на бэкенд и рисовать
мокап, нужно точно знать, что уже отдают существующие схемы и эндпоинты.

## Что посмотреть (файлы)

- `backend/app/schemas/` — схемы категорий и уроков
- `backend/app/services/` — сервисы категорий и уроков
- `backend/app/api/v1/` — роуты categories и lessons
- `backend/app/models/` — модели Category, Lesson, LessonRole

## Вопросы, на которые нужен ответ

### 1. Категории

- Какие поля возвращает `GET /api/categories/` (схема `CategoryTree` или
  аналог)? Есть ли в ответе `order`, `parent_id`, `slug`?
- Что принимает `PATCH /api/category/`? Можно ли через него поменять
  `order`, `parent_id`, `name`, `slug`?
- Видит ли master через `GET /api/categories/` ВСЕ категории, включая
  пустые (без уроков)? Как работает фильтрация по роли для privileged?
- Что происходит при `DELETE /api/category/?id=`, если категория не пуста
  (есть уроки или подкатегории)? Какой код и текст ошибки?

### 2. Уроки — список

- Какие поля в схеме `LessonCard` (`GET /api/lessons/`)? Конкретно:
  есть ли `category_id`, `is_public`, `order`, `vimeo_id`, список ролей?
- Видит ли master в этом списке ВСЕ уроки (включая уроки без ролей и
  не-public)? Есть ли уроки, которые master НЕ увидит?

### 3. Урок — полный

- Какие поля в схеме `LessonOut` (`GET /api/lesson/{lesson_id}`)?
  Конкретно: есть ли список ролей (`roles` — в каком виде: ключи, id,
  объекты?), `order`, `transcript`, `thumbnail_url`, `slug`?
- Что принимает `POST /api/lesson/` и `PATCH /api/lesson/`? В каком
  формате передаются роли видимости? Как задаётся `is_public`?

### 4. Порядок (order)

- Как сейчас назначается `order` при создании категории/урока
  (автоматически max+1? вручную? default 0?)?
- Есть ли где-то в сервисах логика пересчёта/сдвига order? (Ожидаем,
  что нет — подтвердить.)
- `order` уникален в пределах чего: всей таблицы, родителя (parent_id),
  категории (category_id)? Или не уникален вовсе?

### 5. Сортировка выдачи

- Сортируются ли категории и уроки в ответах по `order`? Если нет —
  по чему (id, created_at)?

## Формат отчёта

По каждому из 5 разделов: краткий ответ + точное содержимое схемы
(поля и типы, как в коде). Если чего-то нет — прямо написать «нет».
В конце — список расхождений с тем, что понадобится интерфейсу
(своими словами, без предложений по реализации — решения примет Jenna).

## Границы

- НЕ менять ни один файл.
- НЕ запускать приложение, docker, миграции.
- НЕ предлагать и не делать «заодно» рефакторинг.
- Можно читать любые файлы репозитория и docs/.
