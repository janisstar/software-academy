# Задача: страница Content / Categories (inline-дерево)

## Контекст

Master-раздел управления категориями каталога. Мокап УТВЕРЖДЁН:
`docs/mockups/content-categories-mockup.html` (4 экрана: дерево,
rename inline, move + add, empty). Следовать ему точно.

Бэкенд готов целиком, типы перегенерированы (`npm run gen:api` уже
выполнен). Используемые эндпоинты:

- `GET /api/categories/` → дерево `CategoryTreeOut[]`, в узлах есть
  `lessons_count`, `subcategories_count`, `order`, `parent_id`
- `POST /api/category/` — тело `{name, parent_id?}` (order НЕ передаётся,
  бэк ставит в конец ряда)
- `PATCH /api/category/` — `{id, name}` (rename) или `{id, parent_id}`
  (перенос; `parent_id: null` = на верхний уровень)
- `POST /api/category/move/` — `{id, direction: "up" | "down"}`
- `DELETE /api/category/?id=`

## Доступ и навигация

- Страница — только для master. Гейт по `activeRole` ДО запроса
  (как на Master Dashboard), не ловля 403. Не-master по прямому URL
  видит ту же заглушку «In development», что и сейчас.
- В `navConfig.ts` пункты группы Content (Categories, Lessons) сделать
  видимыми только master — тем же механизмом, каким Companies скрыта
  от не-master. Lessons остаётся заглушкой, её страницу не трогать.

## Структура (interface-based, как везде)

- Страница: `pages/master/` — заменить содержимое существующей
  заглушки Categories.
- Компоненты: `components/master/` — `CategoriesTree` (карточка-дерево)
  и `CategoryRow` (строка со всеми inline-состояниями). Если чисто —
  можно одним компонентом; два — если строка разрастается. Свой
  `CategoriesTree.module.css` (НЕ переиспользовать чужие module.css).
- Хук: `hooks/useCategoriesTree` — загрузка + `reload()`, паттерн

  с Retry, как в People).
- Типы — только из codegen-псевдонимов (`src/types/api.ts`); если
  псевдонима для дерева/move-запросов нет — добавить псевдоним,

- Все строки UI — ключи i18n в `src/i18n/locales/en.json`
  (раздел `content.categories.*`), тексты — из мокапа.
- Переиспользовать ui-компоненты: `Button` (варианты уже есть),
  `Select` (для Move), `PageShell` с `actions` (кнопка Add category).
  Инпут inline-редактирования: если `TextField` встраивается в строку

## Поведение

### Дерево

- Рендер строго по порядку ответа бэка (он уже сортирует по order) —
  НИКАКОЙ клиентской сортировки.
- Подкатегории — с отступом и рельсой, как в мокапе. После детей
  каждого родителя — строка «+ Add subcategory».
- Счётчики: «4 lessons · 2 subcategories» (части опускаются, если 0;
  оба нуля → «No lessons»), формат из мокапа.
- Действия строки видимы при hover И при focus-within (клавиатура!) —
  в мокапе это уже сделано через opacity.

### Порядок (▲▼)

- ▲ disabled у первой записи ряда, ▼ у последней (ряд = соседи с тем
  же parent_id). Клик → `POST /api/category/move/` → `reload()` дерева.
  Никаких оптимистичных перестановок на клиенте.
- Ответ `{"status": "noop"}` — просто ничего не делать (кнопки на краях
  и так погашены, это подстраховка).

### Inline-состояния строки

Одновременно редактируется ТОЛЬКО одна строка: открытие любого
редактора (rename / move / add) закрывает предыдущий без сохранения.

- **Rename**: имя → input (текущее значение, автофокус, текст выделен),
  Save / Cancel; Enter = Save, Esc = Cancel. Пустое имя — Save disabled.
  Save → `PATCH {id, name}` → reload.
- **Move**: в строке селект «Move to:» — опции: «Top level» + все
  категории ВЕРХНЕГО уровня кроме самой себя; текущий родитель
  помечен «(current)» и предвыбран. «Move here» disabled, пока выбран
  текущий родитель. Подтверждение → `PATCH {id, parent_id}`
  (null для Top level) → reload.
- **Delete**: кнопка disabled, если `lessons_count > 0` или
  `subcategories_count > 0`, с title из мокапа
  («Only an empty category can be deleted»). Активная кнопка →
  confirm-модалка (существующий `Modal`, по образцу Delete у
  пользователя) → `DELETE` → reload.
- **Add category** (кнопка PageShell) → строка-форма в конце верхнего
  уровня; **+ Add subcategory** → строка-форма в конце детей родителя.
  Обе: input + Create / Cancel, Enter/Esc, пустое имя — Create disabled.
  Create → `POST {name, parent_id?}` → reload.
- Во время редактирования строки её ▲▼ disabled (как в мокапе).

### ⚠️ Отклонение от мокапа — Move у категории с подкатегориями

Бэк запрещает категории с подкатегориями становиться подкатегорией
(400), а перенос «Top level → Top level» бессмысленен. Поэтому:
у строки с `subcategories_count > 0` кнопка Move **disabled** с title
«Move its subcategories out first». В мокапе Move у Welding активна —
это сознательная правка, Jenna в курсе.

### Ошибки и загрузка

- Ошибка загрузки дерева → состояние страницы с Retry (как People).
- Ошибка мутации (PATCH/POST/DELETE/move) → текст бэка через
  `utils/apiError.ts` красным капшеном ВНУТРИ активной строки
  (редактор не закрывать — ввод не теряется). Для move-кнопок
  (ошибка маловероятна) — допустимо показать ошибку в том же месте
  строки без редактора.
- Пока мутация летит — кнопки Save/Create/Move here/Delete disabled
  (защита от даблклика).
- Пустое дерево → empty state из экрана 4.

## Чего НЕ делать

- НЕ трогать страницу Lessons, учебный каталог, бэкенд.
- НЕ делать drag&drop, никаких библиотек не добавлять.
- НЕ кэшировать/сортировать дерево на клиенте — источник порядка
  только ответ бэка.
- НЕ переводить старые экраны на i18n (отложено) — ключи только
  для новой страницы.

## Testing guide (напиши свой по этому скелету)

Dev: docker compose up -d + npm run dev, вход keimo.

1. /content/categories: дерево = данные из Swagger-тестов (A, B, C,
   подкатегории), порядок и счётчики совпадают.
2. ▲▼: перестановки работают, края погашены, после клика дерево
   перезагружается в новом порядке.
3. Rename: Enter/Esc, пустое имя, ошибка бэка (придумать способ).
4. Move: селект, предвыбор «(current)», перенос под другого родителя
   и на Top level; у категории с подкатегориями Move погашена.
5. Add category / Add subcategory: создание, новая — в конце ряда.
6. Delete: погашена у непустой, confirm у пустой, после удаления
   строка исчезла.
7. Только одна строка в редакторе: открыть rename, кликнуть Move
   в другой строке — первый редактор закрылся.
8. Не-master (тестовый admin): пунктов Content нет в навигации,
   прямой URL → заглушка, запросов к API нет (вкладка Network).
9. Клавиатура: Tab по строке проявляет действия, фокус видим.
